# G0 — the per-batch file-placement check (spec `harness/code-organization.md`, Step 1.0)

Spec: `docs/contributor_manual/specs/harness/code-organization.md` (APPROVED by the owner 2026-11-14). Behaviour this lane
builds: `code-org.enforce.per-batch-placement`. Milestone `code-organization`. This is the FIRST enforcement step: every
batch after it is judged by what you build here. You write one new guard and its tests; you move no code.

## What to build

`scripts/check_file_placement.py` with ONE mode in this lane, `--since <base>` (G1 adds the whole-tree mode to the same
file later; design the rule table as data so G1 and G2 only add rows). Stdlib only, importing `_scan_files` and
`_check_floor` like its neighbours. Read first: `scripts/check_swiftlint_warning_ratchet.py` (the `--since` shape,
#6318: merge-base, `git show` of both trees, exit 2 when blind) and `scripts/check_folder_organization.py` (the
allowlist and scan-floor shape).

Behaviour:
1. `base = git merge-base HEAD <base>`; `git diff --name-status -M base..HEAD`. Take every `A` path and the NEW path of
   every `R…` row. Deleted (`D`) and modified-in-place (`M`) files are not judged (the tree's old debt is the nightly
   whole-tree guard's, G1).
2. Judge each path against the rules below. Red = exit 1, one line per misplaced file: the path, ` → `, the folder it
   belongs in, the rule in a few words (e.g. `fichero-server/src/fichero_server/foo.py → fichero_server/<package>/foo.py:
   the package root holds only __init__ and __main__`).
3. Exit 0 when every added or renamed file is in place, and print how many were judged (never a silent 0 on zero files
   when the diff failed). Exit 2 (BLIND) when git fails, the base is unknown, or the diff cannot be parsed.

Rules in this lane (Python and the repo root; G2 adds the Swift rules):
- **Repo root**: a new path with no `/` in it is red unless in the allowlist of spec bullet `code-org.folders.root`
  (copy it as data; `.gitignore`, `.gitattributes`, `.gitmodules` and `.github/` are allowed too).
- **Engine package root**: a new `.py` directly under `fichero-server/src/fichero_server/` is red ("→ fichero_server/<package>/,
  the package of what it does"); only `__init__.py` and `__main__.py` live there.
- **`api/routes/` root**: a new `.py` directly under `fichero-server/src/fichero_server/api/routes/` is red ("→ api/routes/<resource>/").
- **No alias module**: a new or renamed `.py` whose text contains `sys.modules[__name__]` is red (AGENTS.md rule 0).
- **Module names**: `^[a-z_][a-z0-9_]*\.py$`, and not `utils.py`, `helpers.py`, `misc.py`, `common.py`.
- **Tests**: a new file under `fichero-server/tests/unit/` must match `^test_[a-z][a-z0-9_]*?(_\d{3,5})?\.py$` (a number
  right after `test_` is red: the issue is a suffix) and sit in `tests/unit/<package>/` for an existing
  `fichero_server/<package>/`, or in `tests/unit/scripts/`, `tests/unit/cli/`, `tests/unit/mcp/`, `tests/unit/harness/`,
  `tests/unit/seams/`; red otherwise ("→ tests/unit/<package>/"). `conftest.py` and `_helper.py` names pass.
- **Sibling products**: the module-name rule under `fichero-cli/src/`, `fichero-mcp/src/`, `fichero-builder/fichero_builder/`.

Wiring: `harness.toml` `since_guards` gains `"scripts/check_file_placement.py" = "fichero-server/"`. The table maps one
guard to one path prefix today; the Swift prefix comes with G2, so make `check_tool.py`'s `since_guards` reader accept a
LIST of prefixes as well as a string, tested in `fichero-builder/tests/test_guard_inputs.py` (harness code lives in the
Builder; this is the one change outside `scripts/`). Keep the guard under 60 s (`guard_timeout_s`).

## Tests (write them first, red on the base)

- `scripts/check_file_placement.py --self-test`: make a scratch git repo (`tempfile` + `git init`), commit a base,
  then add one RIGHT and one WRONG file per rule above (adds and renames), run the `--since` logic over it and assert
  exactly the wrong ones are reported with the right destination; assert a broken base gives exit 2; print `self-test ok`;
  exit 1 if the guard sees nothing (a guard must know when it is blind, AGENTS.md rule 0).
- `fichero-server/tests/unit/scripts/test_check_file_placement.py`: runs the self-test as a subprocess (pattern:
  `tests/unit/scripts/test_spec_guards_self_test_5729.py`), and runs `--since origin/integration` on HEAD asserting exit 0.
  Docstring: `spec: code-organization` and the behaviour id.
- `fichero-builder/tests/test_guard_inputs.py`: the `since_guards` list form.
- `fichero-server/tests/unit/scripts/test_every_guard_passes_on_the_real_tree.py` picks the new guard up by glob: run it
  (the no-flag form must exit 0 or 2 with a clear "use --since" line, never 1, until G1 adds the whole-tree mode).

## Guards to run, the base way

From the repo root, exactly as the gate runs them: `python3 scripts/check_file_placement.py --since origin/integration`;
`python3 scripts/check_python_comment_hygiene.py`; `python3 scripts/check_harness_neutral.py` (the guard names no project
by name beyond the rules file); `ruff check scripts/check_file_placement.py fichero-server/tests/unit/scripts/test_check_file_placement.py`;
then `scripts/lane_ready_check.sh HEAD` (exit 0 = READY). The pytest files: `PYTHONPATH=fichero-server/src python -m pytest
fichero-server/tests/unit/scripts/test_check_file_placement.py fichero-builder/tests/test_guard_inputs.py -q`.

## Done when

The guard exits 0 on HEAD against `origin/integration`, `--self-test` prints `self-test ok`, the pytest files pass,
`harness.toml` carries the `since_guards` entry, and the spec bullet `code-org.enforce.per-batch-placement` flips to [OK]
with a `Test:` line naming the test file (tag, issue number and `Test:` are the free edits; do not reword acceptance
text). One commit; cite the issue the manager filed for this lane in the subject (`(#NNNN)`) and the behaviour id in the
body; trailers as the lane requires. Nothing moves.
