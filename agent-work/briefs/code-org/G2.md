# G2 — the Swift file guard (spec `harness/code-organization.md`, Step 1.2)

Spec: `docs/contributor_manual/specs/harness/code-organization.md` (APPROVED 2026-11-14). Behaviours this lane builds:
`code-org.naming.swift-file-is-type`, `code-org.folders.swift-view-local-state`, `code-org.folders.swift-test-mirror`,
and the Swift rules of `code-org.enforce.per-batch-placement` (G1 built the guard and its Python rules; this lane adds
the Swift rules to the same table). You write guards and tests; you move no code and edit no `.swift` file.

## What to build

A. `scripts/check_swift_one_type_per_file.py` (new, stdlib only, `_scan_files` + `_check_floor`). Over
`fichero/fichero/**/*.swift` (skip `fichero-api-client`, `*Generated.swift`, `*.generated.swift`), strip comments and
strings, then:
1. **One primary type.** Count top-level `struct|class|enum|actor|protocol` declarations that are not `private`/
   `fileprivate`. More than ONE public-ish top-level type is a finding, except: a file named `<Service>Types.swift` or
   `<X>WireModels.swift` under `Services/` (the owner keeps these wire bundles, ruling 2 of 2026-11-14); `#Preview` and
   `*Preview` types; a `Type+Topic.swift` extension file whose extra types are `private`.
2. **File named for its type.** For a file with no `+`, the stem equals one of its top-level type names (or a declared
   type name starts with the stem, for `FooView.swift` holding `FooViewModel` beside `FooView`). A `Type+Topic.swift`
   file must contain `extension Type`.
3. **Views end in a shape word.** A type conforming to `View` (`: View`, `: some View` on `body`) ends in one of:
   `View Pane Sheet Row Bar Button Menu Picker Popover Cell Badge Label Overlay Section Item Field Panel Strip Card Line
   Notice Pill Host Content Modifier Stage Screen Page Tab Tabs Toolbar Header Footer Chip Indicator Banner Grid List
   Stack Canvas Editor Viewer Inspector Reader Sidebar Window Scene Renderer Commands`. A `View` type outside `Views/`
   is a finding unless under `App/Menus/` or named `*Scene`/`*Window` under `App/`.
4. **Platform suffix.** A file or type ending `iOS`, `macOS`, `iOSOnly` is a finding: the spelling is `IOS` / `MacOS`
   (owner ruling 4 of 2026-11-14). Today: `DocumentKGWebPaneCoordinatoriOS.swift`, `FullScreenImagePreviewIOSOnly.swift`.
`KNOWN_VIOLATIONS` baselines today's tree (the review counts 135 misnamed files and 303 multi-type files; generate the
dict with `--generate`, one line per file with the count of findings; the count may only fall). `--list`, `--self-test`
(plant each kind of finding in a scratch tree), exit 2 when the scan floor (400 Swift files) is not met.

B. `scripts/check_folder_organization.py` gains, beside its 18-file rule:
- a folder under `Views/` with ONE `.swift` file and no subfolder is a finding ("fold into the feature that opens it");
- a folder under `Views/` named for a layer (`Models`, `Services`, `Views`, `Helpers`, `Utils`, `Misc`, `Common`,
  `Shared`) is a finding;
- `KNOWN_VIOLATIONS` entries carry the file count at baseline; a count above it FAILS (today every entry has grown since
  it was written: `Models` 53→355, `Services` 60→220). Re-seed the dict at today's counts with `--generate`.
- **Test mirror**: for a test file under `fichero/Tests/Unit/<platform>/Views/<A>/<B>/FooTests.swift`, the app folder
  `fichero/fichero/Views/<A>/<B>/` must exist (and the same for `Models/`, `Services/`, `App/`, `Intents/`); a test folder
  with no app folder is a finding. Report only; baseline today's.
- **View-local state** (ruling 1): an `@Observable` or `ObservableObject` type declared under `Views/<Feature>/` whose
  name is used from a `.swift` file under a DIFFERENT `Views/<Other>/` or under `App/` is reported with "→ Models/<Feature>/
  (read by two features)"; one feature's own state beside its views passes. Baseline today's.

C. `scripts/check_file_placement.py` (from G1) gains the Swift rules for added/renamed files: a new `.swift` under
`fichero/fichero/` is under one of `App/ Models/ Services/ Intents/ Views/ Resources/`; a new `View` type is under
`Views/<Feature>/` or `App/Menus/`; the file name passes rules 2–4 above; a new test under `fichero/Tests/Unit/` is
under the mirror folder of an existing app folder and ends `Tests.swift`. `harness.toml` `since_guards` gets the
`fichero/` prefix for the guard (see G1 on one-prefix-per-guard).
