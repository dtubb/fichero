# G1 — the whole-tree layout mode of the placement guard (spec `harness/code-organization.md`, Step 1.1)

Spec: `docs/contributor_manual/specs/harness/code-organization.md` (APPROVED 2026-11-14). Behaviours this lane builds:
`code-org.folders.root`, `code-org.folders.python-packages`,
`code-org.folders.python-no-shim-modules`, `code-org.folders.python-test-mirror`, `code-org.naming.python-tests`.
Milestone `code-organization`. You write ONE new guard and its tests; you move no code.

## What to build

G0 built `scripts/check_file_placement.py` with its `--since <base>` per-batch mode and the Python and root rules as a data
table. This lane adds the WHOLE-TREE mode to the same file (no second guard), stdlib only, importing only `_scan_files` and `_check_floor` like its neighbours
(read `scripts/check_folder_organization.py` and `scripts/check_swiftlint_warning_ratchet.py` first: the first for the
allowlist/scan-floor shape, the second for the `--since <base>` shape, #6318). Two modes, one rule table:

1. `--since <base>` (per batch) EXISTS from G0 and is not changed here beyond the shared rule table. Run `git diff --name-status
   <merge-base of HEAD and base>..HEAD`; take every `A` (added) path and the NEW name of every `R` (renamed) path. Judge
   each against the rules below. Deleted and modified-in-place files are not judged. Exit 1 with one line per misplaced
   file: the path, an arrow, the folder it belongs in, the rule in a few words. Exit 0 when every added/renamed file is
   in place. Exit 2 (BLIND) when git fails or the base is unknown; never 0 on a failure to measure.
2. No flag (whole tree, nightly): the same rules over the whole tree, against a `KNOWN_VIOLATIONS` dict baselined on
   today's tree (the spec and the review list the debt: 18 loose engine modules, 18 shim modules, the unmatched test
   dirs). The dict carries a count per entry; a count that rises fails; an entry whose path is gone fails (the list only
   shrinks). Add it to `harness.toml` `guard_skip` with a reason, like `check_swiftlint_warning_ratchet` (the whole-tree
   question is nightly; the `--since` question is per batch).

Rules (G0's table, reused by the whole-tree mode; the Swift rules come in G2 and plug into the same table):
- **Repo root**: nothing new at the repo root beyond the spec's allowlist in `code-org.folders.root` (copy that list
  verbatim as data; `.gitignore`, `.github/`, `.gitattributes`, `.gitmodules` are allowed too).
- **Engine package root**: `fichero-server/src/fichero_server/` holds only `__init__.py` and `__main__.py`; a new module
  there is red with "→ fichero_server/<package>/ (the package of what it does)".
- **`api/routes/` root**: a new module directly under `fichero-server/src/fichero_server/api/routes/` is red
  ("→ api/routes/<resource>/").
- **No shim module**: a new or renamed `.py` whose text contains `sys.modules[__name__]` is red (AGENTS.md rule 0).
- **Module names**: `snake_case` only (`^[a-z_][a-z0-9_]*\.py$`), and not `utils.py`/`helpers.py`/`misc.py`.
- **Tests**: a new file under `fichero-server/tests/unit/` must be `test_<what>.py` or `test_<what>_<issue>.py`
  (`^test_[a-z][a-z0-9_]*?(_\d{3,5})?\.py$`; a leading number after `test_` is red); its folder must be one of
  `tests/unit/<package>/` for an existing `fichero_server/<package>/`, or `tests/unit/scripts/` (tests of `scripts/`),
  `tests/unit/cli/`, `tests/unit/mcp/`, `tests/unit/harness/`; red otherwise with "→ tests/unit/<package>/".
- **Sibling products**: the same module-name rule under `fichero-cli/src/`, `fichero-mcp/src/`, `fichero-builder/`.

Wiring: G0 put the guard in `harness.toml` `since_guards`; this lane adds the whole-tree mode to `guard_skip` with a reason
(nightly, like `check_swiftlint_warning_ratchet`). Run time of the whole-tree mode may exceed 60 s; the per-batch mode stays under.

## Tests (write them first, red on the base)

- `scripts/check_file_placement.py --self-test`: build a scratch git repo with one right and one wrong file PER RULE
  above (added and renamed), run the `--since` mode over it, assert exactly the wrong ones are named with the right
  destination; assert the whole-tree mode on a scratch tree with a planted loose module fails and with none passes;
  print `self-test ok`. Exit 1 if the guard is blind (sees nothing). Pattern: `scripts/check_spec_behaviors_are_tagged.py`.
- `fichero-server/tests/unit/scripts/test_check_file_placement.py`: runs the self-test (as
  `tests/unit/scripts/test_spec_guards_self_test_5729.py` does), runs the whole-tree mode on the real tree and asserts
  exit 0 (the baseline covers today's debt), runs `--since origin/integration` on HEAD and asserts exit 0.
- `fichero-server/tests/unit/scripts/test_every_guard_passes_on_the_real_tree.py` picks the new guard up by glob: run it.
- Docstring cites the spec: `spec: code-organization`.

## Guards to run, the base way

From the repo root, as the gate runs them: `python3 scripts/check_file_placement.py` (no flag: the whole-tree mode, exit 0 on
the baseline), `python3 scripts/check_file_placement.py --since origin/integration`, `python3 scripts/check_python_comment_hygiene.py`,
`ruff check scripts/check_file_placement.py`, `PYTHONPATH=fichero-server/src python -m pytest fichero-server/tests/unit/scripts/test_check_file_placement.py -q`,
then `scripts/lane_ready_check.sh HEAD`.

## Done when

`python3 scripts/check_file_placement.py` exits 0; `--since origin/integration` exits 0; `--self-test` prints `self-test
ok`; the two pytest files pass; `harness.toml` carries the `since_guards` entry and the `guard_skip` line with a reason;
the spec's bullets for the six behaviours flip to [OK] with `Test:` lines naming the test file (tags, issue numbers and
`Test:` lines are the free edits; do not reword acceptance text). One commit; cite the lane's issue `(#NNNN)` in the subject and the behaviour ids in the body; trailers as the
lane requires. Nothing moves; the review's P1/P2/P3 lanes do the moves and are judged by this guard.
