# V1 — the swift-openapi-generator range cap (spec `harness/code-organization.md`, Step 1.4)

Spec: `docs/contributor_manual/specs/harness/code-organization.md` (APPROVED by the owner 2026-11-14). Behaviour:
`code-org.ratchet.generated-warnings-fixed-at-source`. Milestone `code-organization`. One package manifest line, one
test, no generated file touched (AGENTS.md rule 3: never edit generator output). Lands before G3 so the compiler-warnings
baseline is measured on one generator everywhere.

## Why

swift-openapi-generator 1.13.0 (its PR #883) writes `@_spi(Generated) public import OpenAPIRuntime` and
`public import struct Foundation.URL/.Data/.Date` at the head of every generated file and splits the output into nine
files; the protocol-only `Types.swift` uses none of them in a public declaration, so the compiler emits
`public import of 'Foundation' was not used in public declarations or inlinable code [#UnusedImportAccess]` three times
and once for `OpenAPIRuntime`. Upstream: apple/swift-openapi-generator issue #968 (duplicate of #946), fix pending in
PR #947 (Swift 6.4 warning suppression). The repo's `fichero/fichero-api-client/Package.resolved` pins the generator at
1.10.3 (warning-free) and the runtime at 1.9.0, but `Package.swift` says `from: "1.6.0"`, so Xcode with automatic
resolution (the owner's Macs: every DerivedData there resolved 1.13.1) builds different, warning-bearing code than the
builder (`-disableAutomaticPackageResolution`). The fix is the package version, not the config (`accessModifier: public`
is required), not a target setting (no per-group suppression before Swift 6.4), not the schema (the warning is per file).

## The change

`fichero/fichero-api-client/Package.swift` line 25:
```swift
.package(url: "https://github.com/apple/swift-openapi-generator", from: "1.6.0"),
```
becomes
```swift
// Below 1.13.0 until apple/swift-openapi-generator#947 ships: 1.13 emits `public import` in every generated file
// and the protocol-only Types.swift warns UnusedImportAccess four times (#968). Lift the cap and re-baseline the
// generated bucket of check_swift_compiler_warning_ratchet in one commit (spec code-org.ratchet.generated-warnings-fixed-at-source).
.package(url: "https://github.com/apple/swift-openapi-generator", "1.6.0"..<"1.13.0"),
```
`Package.resolved` stays at 1.10.3 / runtime 1.9.0 (no resolution run is needed; the pin already satisfies the range).
Do NOT run `swift package update` or let Xcode resolve: the pin is what the builder builds. If the manager wants the
last warning-free release instead (1.12.2), that is a separate, deliberate `Package.resolved` change with its runtime.

## The test (first, red on the base)

`fichero/fichero-api-client/Tests/FicheroAPIClientTests/GeneratorRangeCapTests.swift` (XCTest, like its neighbours):
reads `Package.swift` relative to `#filePath` (`../../Package.swift`), asserts the generator dependency line contains
`"1.6.0"..<"1.13.0"` and not `from: "1.6.0"`, and reads `Package.resolved` asserting the `swift-openapi-generator` pin
version is below 1.13.0 (parse the JSON, compare the leading integer pair). Docstring cites
`spec: code-organization` and `code-org.ratchet.generated-warnings-fixed-at-source`. The file is under the package's
synchronized test folder: no `project.pbxproj` edit, no registration script.

## Guards to run, the base way

From the repo root: `python3 scripts/check_openapi_client_parity.py`, `python3 scripts/check_contract_identity_current.py`
and `python3 scripts/check_openapi_version_current.py` (the contract did not change, they stay green);
`python3 scripts/check_xcode_registration.py`; `swiftlint lint --quiet fichero/fichero-api-client/Tests`; then
`scripts/lane_ready_check.sh HEAD`. The package test runs with the Dev Local scheme's test plan on the M4 (the manager
runs it; no `xcodebuild` on the laptop, no test run beside the owner's app). The build rung compiles the package: a
clean build log after this lane shows zero `UnusedImportAccess` lines under `BuildToolPluginIntermediates`, which G3's
generated-bucket baseline then records as 0.
