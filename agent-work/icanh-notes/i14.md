## [test] What's missing
There is no regression test that pins the core "one page at a time" contract for image-only scanned PDFs — the exact thing #2222 broke. The behavior is currently spread across `files_tool` fan-out, `builder` Send fan-out, and `process_vision`, with no end-to-end assertion.

## Why it matters
The per-page guarantee depends on a fragile chain: page children must exist at ingest → `_expand_to_pages` gates on `file_type==pdf` AND `doc_type==page` → source must be a `SOURCE_TOOLS` node wired directly to a `PARALLEL_TOOLS` node → `process_vision` must see `requested_page_index`. Any link breaking silently reverts to whole-PDF (#2222, and #1 in this milestone). Nothing tests the whole chain.

## Test that should exist
End-to-end (mocked `vision()`): build the default Transcribe workflow over a 3-page image-only PDF with 3 page children; assert
1. exactly 3 vision calls (one per page), each with a single rendered page image — never the whole PDF;
2. each page child gets its own `page_content` + transcription artifact with the correct `doc_id`;
3. the parent doc does not receive a combined whole-PDF transcript;
4. re-running hits the per-page cache (0 new vision calls).
Add sibling tests for the Auto-Detect and Catalogue presets so each preset is proven to honor per-page output.
