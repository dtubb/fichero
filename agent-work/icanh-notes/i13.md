## What's fragile
Even after the #2215 per-page LLM loop, the whole-PDF path (no fan-out) still writes the **entire concatenated transcript** as one artifact AND into `page_content` on the PARENT document. The hard principle is one-page-at-a-time output to the page child, never a whole-PDF transcript on the parent (it bloats the parent and is the artifact users saw "stuck" on the parent in #2222).

## Why
`vision_base.py:1894-1917`: `save_artifact(..., document_id=doc_id_for_file, content=text)` where `text` is the full `"\n\n".join` of every page (`:1779`) and `doc_id_for_file` is the parent when `requested_page_index is None`. `_propagate_to_page_children` then ALSO writes per-page — so the parent ends up with a giant combined transcript while children get their slices. For a 200-page PDF the parent artifact/`page_content` is enormous.

## Fix sketch
When page children exist, write per-page artifacts/`page_content` to children only and skip the combined parent transcript (or store only a short file-level marker, not the full concatenation). Prefer driving everything through the per-page fan-out so the whole-PDF branch is a rare fallback, and when it is hit, still attribute per page.

## Test that should exist
Whole-PDF path on a 3-page PDF with page children; assert each page child holds exactly its own page text and the parent does NOT hold the full 3-page concatenation in `page_content`/artifact.
