# 0.0.1 Manual QA Checklist

Purpose: release-gate checklist for the approved 0.0.1 surface.

## 1. Core Startup and Build
- [ ] Clean clone/build succeeds in Xcode Debug and Release.
- [ ] App launches with backend reachable and no fatal startup dialogs.
- [ ] SwiftLint build phase runs without blocking errors.

## 2. Library Essentials (0.0.1 Surface)
- [ ] Create/open/save library works across relaunch.
- [ ] Add files/folders via Data menu and sidebar plus button.
- [ ] Selection persists when switching views and relaunching.
- [ ] Delete removes items from sidebar and does not reappear.
- [ ] Inspector text panel supports edit/save/revert.

## 3. Search Essentials (0.0.1 Surface)
- [ ] Search tab opens from keyboard/menu when enabled.
- [ ] Search returns expected results for known seeded documents.
- [ ] Clearing search restores default state without stale filters.

## 4. Workflow Essentials (Approved 0.0.1 Slice)
- [ ] Create/rename/delete workflow from sidebar persists across relaunch.
- [ ] Canvas editing works with approved release tools only.
- [ ] Run workflow on selected documents completes and writes artifacts.
- [ ] Output log updates during execution.

## 5. Data Integrity and Cleanup
- [ ] Deleting a parent document removes descendants.
- [ ] No orphaned artifacts remain after cascaded deletes.
- [ ] `POST /api/documents/cleanup-orphans` returns `0` in normal flows.

## 6. Updater
- [ ] Sparkle menu item opens updater without crash loops.
- [ ] `SUFeedURL` and `SUPublicEDKey` are configured for release path.

## 7. Evidence Required Per Run
- [ ] Commit SHA and build number.
- [ ] `xcodebuild test` summary.
- [ ] `pytest` summary for backend checks.
- [ ] Screenshot/video for each failing gate.

## 8. Feature-Gate UI Verification (Release Tier)
- [ ] Off-tier sidebar modes are hidden (`chat`, `batches`, `automation`, `activity`).
- [ ] Off-tier menu entries are hidden (`MCP`, integrations, provider settings in release tier).
- [ ] Non-release tooling is not discoverable in workflow/editor menus.

## 9. Feature-Gate Backend Verification (Release Tier)
- [ ] Off-tier routes return `404` (or are absent from OpenAPI) at release tier:
  - [ ] `/api/workflow-execution/*`
  - [ ] `/api/integrations/*`
  - [ ] `/api/actions/*`
  - [ ] `/api/mcp-servers/*`
  - [ ] `/api/chains/*`
  - [ ] `/api/local-models/*`
  - [ ] `/api/model-comparison/*`
- [ ] Providers/models routes are not available unless backend tier is dev.

## 10. Dev Override Clarification
- [ ] `FICHERO_ALL_FEATURES=1` affects frontend-only feature switches.
- [ ] Backend dev surfaces require `FICHERO_FEATURE_TIER=dev` separately.
- [ ] QA notes include which frontend/backend tier flags were active.

## 11. Targeted Regression Checks (Current 0.0.1 Bugs)

### 11.1 Drag and Drop: Create File/Folder from Finder Into Library
- [ ] Preconditions:
  - [ ] App launched with backend running.
  - [ ] A non-empty library is open and visible in Library mode.
  - [ ] Finder window open with at least one file and one folder.
- [ ] Manual steps:
  1. Drag a single file from Finder into the center Library view.
  2. Drop onto blank space (root level).
  3. Drag a folder from Finder into the same Library view.
  4. Drop onto blank space (root level).
  5. Drag a file onto an existing folder row/card in the library.
  6. Verify sidebar and center pane both refresh.
- [ ] Expected:
  - [ ] File import creates a new document item and preview works.
  - [ ] Folder import creates a folder entry (with children when applicable).
  - [ ] Drop on folder targets that folder as parent.
  - [ ] No silent failures; user sees success or actionable error.

### 11.2 Image Import (File Type Handling)
- [ ] Preconditions:
  - [ ] Include at least one `.jpg` or `.png` file and one non-image control file.
- [ ] Manual steps:
  1. Use `Data -> Add File...` and choose an image.
  2. Use sidebar `+` import flow and choose an image.
  3. Drag the same image from Finder into Library view.
  4. Select imported image and open preview pane.
  5. Repeat with at least one additional image format used in your corpus.
- [ ] Expected:
  - [ ] Image appears in library and is selectable.
  - [ ] Thumbnail and preview load without API error banner.
  - [ ] Metadata (name/type/path) is populated.
  - [ ] Behavior matches folder/file import flows (no image-only failure mode).

### 11.3 New Database Window + Session Restore
- [ ] Preconditions:
  - [ ] Start with one open library window.
- [ ] Manual steps:
  1. Create a new database/library from the app UI.
  2. Confirm a new window opens for the new library.
  3. In each open window, navigate to different selected items.
  4. Quit app normally (`Cmd+Q`).
  5. Relaunch app.
  6. Verify which windows reopen and which library each is bound to.
  7. Repeat once after opening a third library window.
- [ ] Expected:
  - [ ] All previously open library windows are restored.
  - [ ] Each restored window is attached to the same library as before quit.
  - [ ] Last selected context is restored per window (or documented fallback).
  - [ ] No duplicate blank windows on relaunch.

## 13. Transcribe + Workflow Reliability Matrix (Release-Blocking)

### 13.1 Single Item Execution
- [ ] Preconditions:
  - [ ] One supported document selected.
  - [ ] One workflow with transcribe-enabled tool path available.
- [ ] Manual steps:
  1. Run transcribe/workflow on a single selected item.
  2. Observe activity/progress while running.
  3. Open resulting output/artifact.
- [ ] Expected:
  - [ ] Run starts and completes without crash/hang.
  - [ ] Progress and completion states are visible.
  - [ ] Output is attached to the correct source item.

### 13.2 Multi-Selection Execution
- [ ] Preconditions:
  - [ ] Select at least 3 mixed items.
- [ ] Manual steps:
  1. Run workflow on current selection.
  2. Verify processed count and per-item status.
  3. Open at least one success output and one failed item (if any).
- [ ] Expected:
  - [ ] `processed + explicit failures == selected input count`.
  - [ ] No silent item drops.
  - [ ] Failures are explicit and actionable in UI/logs.

### 13.3 Folder/Collection Execution
- [ ] Preconditions:
  - [ ] Folder/collection contains multiple items (including at least one larger file).
- [ ] Manual steps:
  1. Run workflow/transcribe targeting the folder/collection.
  2. Observe batch progression and completion.
  3. Verify outputs map back to source files.
- [ ] Expected:
  - [ ] Folder-scope run is stable and completes.
  - [ ] Item accounting is exact.
  - [ ] Output/artifact mapping is correct.

### 13.4 Failure Path Verification
- [ ] Manual steps:
  1. Trigger one known-bad input or unavailable dependency case.
  2. Run workflow/transcribe for single item and selection modes.
- [ ] Expected:
  - [ ] No crash.
  - [ ] Explicit error surfaced (not silent failure).
  - [ ] Partial successes still persist correctly.
