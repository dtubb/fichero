## 1. Setting up a project

Spec: `specs/source/models-chains-and-projects.md`. The maintainer's section will be
"Setting up a project".

### What a person can do

- Answer five questions about a project: its purpose, its material, what it is, how it will be
  done, and Start.
- Fichero proposes a recipe from the answers. Nothing runs until the person presses **Start**.
- Leaving any of the first four screens with **Continue** saves a draft. Reopening setup picks
  the draft up again.
- Later, they can add a language or a layer to the project from the Inspector's **Recipe**
  section.

### Where it is reached

- **File › Set Up Project…** (`App/Menus/FileMenuCommands.swift:118`). There is no keyboard
  shortcut, and the item is disabled when no project window is focused (`:121`).
- A **Set Up…** button in the main view of an empty project
  (`Views/Library/LibraryView+FilterAndBatch.swift:477`; shown only when the project is loaded
  and empty, `App/LibraryWindow.swift:45-52`).
- A **Set Up…** button in the Project Inspector's **Recipe** section
  (`Views/Inspector/Project/ProjectInspector.swift:56,67`).
- A **Set Up…** button in the Document Inspector, under Info › **Recipe**
  (`RecipeStepsView.swift:170`).
- Creating a new project opens setup by itself (`Models/LibraryManager+Operations.swift:239`).

All of these open the same sheet (`FirstRunWindow(setUp: true)`, `LibraryWindow.swift:295`).

## 2. The Activity window and popover

Spec: `specs/ui/activity-and-automatic-work.md`. The maintainer's section will be "What Fichero
is doing".

### What a person can do

- See every run in every open project, opened out into its steps and each step's pages.
- Pause, resume or stop a run, a step or a page.
- Group the rows by project.
- From the toolbar popover, see at a glance what is running, what is waiting and why, and the
  state of this Mac.
- Read in the window's footer why a project's activity could not be loaded.

### Where it is reached

- **Window › Activity**, ⌥⌘0 (`FicheroApp.swift:653-666`).
- The activity button in the main window's toolbar opens the popover
  (`ActivityStatusToolbarItem.swift`). The popover ends with **Open Activity**.
- Double-clicking a run opens its own **Activity Detail** window
  (`ActivityMonitorWindow.swift:130-133`).

### What they see

**The toolbar button** changes with the state:
- idle: tooltip "Background activity — click to view"
- working: a spinner, with a count when more than one task runs
- an error: a red glyph, tooltip "A background task reported an error — click for details"

**The window** is one table. Rows open out: run › steps › pages (`ActivityMonitorWindow.swift:115,122`).
Work that belongs to no run, such as an embedding queue, is a row of its own.

Columns (`ActivityMonitorWindow.swift:82-110`):

| Column | Shows |
|---|---|
| **Name** | the name, prefixed "Project · " when not grouped |
| **State** | an icon and one word from Running, Waiting, Paused, Failed, Stopped or Done, with a reason when there is one: "Waiting: memory is tight", "Failed: …" |
| **Progress** | "12 of 40", plus "about N left" while running |
| **Started** | the time it started |
| **Time** | a live timer |
| **Cost** | "$0.0023", "Not priced", or blank |
| **Errors** | a red count |
| **Model** | the model used |
| (no title) | the row's controls |

Every column sorts. The default order puts live rows first, then the newest
(`ActivityMonitorModel.swift:187-190`).

**Row controls** (`ActivityMonitorModel.swift:67-84,167-174`):
- They are icon buttons named **Pause**, **Resume** and **Stop**. Running or waiting rows offer
  Pause and Stop; paused rows offer Resume and Stop; finished rows offer nothing.
- None asks for confirmation.
- A failure shows in the footer as "Couldn't pause|resume|stop &lt;name&gt;: &lt;cause&gt;".
- **Clear Failed** is in the toolbar.
- **Delete** is on the right-click menu and the Delete key. It refuses a run that is still
  running.

**Group by Project** is a toolbar toggle (`ActivityMonitorWindow.swift:64-69`).
- Tooltip: "Group the rows by project, with this Mac's own work as a group of its own".
- Off by default, and remembered across launches.
- This Mac's own work is a group titled "This Mac".

**Empty states** (`ActivityMonitorWindow.swift:44-55`):
- "No Library Open": "Open a library to monitor its workflow activity."
- "No Runs Yet": "Workflow runs from every open library appear here."

**The popover**, from top to bottom (`ActivityPopoverSummary.swift`, `ActivityStatusToolbarItem.swift:113-166`):
1. "Activity" and the project name.
2. What is running, each with "N of M", or "Nothing running."
3. "N waiting" or "N waiting: &lt;reason&gt;".
4. When it applies, a held-back line, one of:
   - "Background work is paused. Work you start still runs."
   - "Heavy work is held back: &lt;reason&gt;"
5. A **This Mac** block:
   - "Memory pressure: normal | warn | critical"
   - "Heat: nominal | fair | serious | critical"
   - "On battery" or "On power"
   - "In use" or "Not in use"

   A reading the engine could not take is left out.
6. "Recent errors" (at most three), a CPU line, and **Open Activity**.

The engine's reasons for holding heavy work back (`server/execution/throttle.py`):
- "Waiting: memory is tight"
- "Waiting: the Mac is hot"
- "Waiting: the Mac is on battery"
- "Waiting: you're using the Mac"

"In use" means input in the last 30 seconds.

**The footer: why a project was refused** (`ActivityStore.swift:324-339`)
- The format is "Couldn't load activity from &lt;Project&gt;: &lt;cause&gt;". The cause is one of:
  - "the engine isn't allowed to open the project from where it's saved"
  - "the engine refused the app's credentials"
  - "the engine could not be reached"
  - the engine's own message, for any other refusal it names
- There is one line per project, with an orange triangle. A line clears when that project next
  loads.
- Since #5468, the app registers its open projects with the engine again on reconnect, so a
  restarted engine no longer refuses them.

## 3. Box colours in Preview, and which pass Preview draws

Spec: `specs/source/segment-editor.md`, section "Box colour and the segment hierarchy". The
maintainer's section will be "Editing the layout of a page".

### What a person can do

- Tell at a glance which lines belong to which region, and in what order they are read.
- Know which reading of a page the boxes come from.
- Turn the boxes on or off.

### Where it is reached

The Preview's "what to show" menu (`ReaderToolbar.swift:217-253`) has:
- **Show Image**
- **Show Annotations**
- **Show Word Bounding Boxes** (the segment boxes)
- **Show Regions** (saved region marks, not segments)
- **Show Text Inline**
- **Edit Segments**

### What they see

**Colour** (`Models/RegionColours.swift`, `SelectionStyle.swift:13-31`):
- Each region takes a hue in turn, in the order the page is written. There are twelve system
  colours: blue, orange, green, purple, pink, teal, indigo, brown, mint, cyan, red, yellow. After
  twelve regions they repeat.
- The lines inside a region are shaded along reading order. The first is full strength and the
  last is lightest, at 45%.
- Words and letters take their line's shade. Region boxes are full strength.
- Lines that sit in no region are treated as one region for the whole page.
- The colours are system colours, so they follow Light, Dark and Increase Contrast.
- In the Inspector's region rows, each swatch is the colour of the box Preview draws for it
  (`ArtifactPanel+Regions.swift:121,164`).

**Which pass is drawn** (`SegmentDisplay.swift:83-102`; engine `server/models/readings.py:596-659`):
- A page may hold several passes of segments. Preview draws one, chosen in this order:
  1. When the Inspector has an artifact of this document in focus, that artifact's passes with
     shapes come first.
  2. Next comes the pass the engine marks as drawn: the best-ranked pass that has shapes.
  3. Then the rest, in the engine's rank.
- The engine ranks passes in this order, newest first within each tier:
  1. a reading someone chose
  2. passes a person touched
  3. text-layer passes
  4. the rest
  5. passes passed over
- When no pass has shapes, no boxes are drawn. The page's working pass is still the one whose
  lines can be picked.
- Georeferencing passes are never drawn as boxes.

### Defaults taken, awaiting a ruling

- Shading always follows the as-written order. Choosing another reading order in the Segments
  pane does not reshade the boxes (`SegmentDisplay.swift:164-167`).
- **Show Word Bounding Boxes** is on by default (#4418), set separately for images and PDFs.
- Not built: a legend for the colours (`source.editor.hierarchy.legend` is [GAP]).

   fading down each region.

## 4. Driving Fichero from outside

Spec: `specs/harness/surfaces-from-openapi.md`. The maintainer's section will be "Driving
Fichero from outside" (MCP, AppleScript, Shortcuts).

### What a person can do

- Connect an AI agent to Fichero through its MCP server.
- Script the app with AppleScript.
- Build Shortcuts from Fichero's actions.

### The MCP server

**What it is.**
- The server lives in `fichero-mcp/`. It runs over stdio as `fichero-mcp`
  (`fichero-mcp/pyproject.toml:39`). To add it to Claude Code:
  `claude mcp add fichero -- fichero-mcp` (`fichero-mcp/README.md:29`).
- It talks to the running app's engine, at `http://127.0.0.1:8765` unless `--api-url` or
  `FICHERO_API_URL` says otherwise.
- There is no Settings pane for it. Settings › MCP manages other MCP servers.

**Where the tools come from.**
- Every tool is generated from the engine's API contract, one tool per operation (event streams
  excepted), by `fichero-server/scripts/generate_openapi_mcp.py` into `openapi_tools_generated.py`.
- At this commit there are 832 tools.
- Tool names read `fichero_<tag>_<action>`, for example `fichero_recipes_start_project`.
- Each tool's description names its route and whether it reads or changes data.
- A guard, `scripts/check_mcp_generated_current.py`, fails when the committed tools differ from
  what the contract would generate. Tools cannot drift from the API.

**Toolsets.**
- A toolset is one tag of the contract.
- By default the server offers the recipe golden path (`server.py:50`): `recipes`, `training`,
  `check`, `segments`, `documents`, `activity`, `local-models`, `hpc`.
- `--toolsets a,b` picks others, and `--toolsets all` gives every one. An unknown name is refused
  with the list of known ones (`server.py:169-178`).
- A few older tool names stay available whatever is chosen: `fichero_health`,
  `fichero_use_library`, `fichero_activity`, `fichero_search` and the like.

The full list of toolsets is in the generated module's `TAGS`:

## 5. Training data quality: the line check, the set preview, the evaluation job

Specs:
- `specs/source/models-chains-and-projects.md` (`source.lines.reading-checked-against-the-page`)
- `specs/compute/jobs-and-fine-tuning.md` (`compute.tune.set-excludes-flagged-lines`)
- `specs/compute/distillation.md` (`distill.eval.*`)

The maintainer's section will be "Making your own model".

**None of this has a screen in the app yet.** It is reached through the API and the MCP tools
only (`scripts/check_endpoint_coverage_matrix_known_gaps.json:283-294`).

### What a person (or their agent) can do

- Check a teacher model's line readings against the page before training on them.
- See exactly what a training set will hold, and what it leaves out, before sending anything.
- Score readers on pages they were not trained on, and keep the scores on each model's card.

### The line check

`server/checking/line_check.py`. The check is called `line-against-page`, and its job is "Check
lines against the page".

**How it works.**
- Kraken reads each line again on that line's own baseline, giving a rough read.
- The teacher's reading is scored against that rough read, and against the rough reads of up to
  two lines either side in the same column.
- The score is 1 − CER, ignoring accents.

**A line is flagged** (`:38-44,73-78`):
- **"closer to a neighbour"**: a neighbouring line's rough read agrees with it at 0.40 or more,
  and by at least 0.15 more than its own line does. This is the shifted-line case.
- **"below the threshold"**: otherwise, when it agrees with its own line under 0.30.

**What follows a flag.**
- The line gets a reject verdict from a model. Its reasons give both scores and the
  neighbour's rough read.
- Lines a person has checked are skipped.
- Empty readings are counted as not scored.
- The job's summary reads "N passed, N closer to a neighbour, N below the threshold".

**MCP tools.**
- `fichero_check_start_run` with `check: "line-against-page"`, layer `readings`, provider
  `kraken`
- `fichero_check_run_status`
- `fichero_check_list_verdicts`
- `fichero_check_cancel_run`

### Flagged lines leave the training set

`server/training/kraken_set.py:147-245`.
- A Kraken training set leaves out lines that are:
  - empty
  - null
  - rejected (their newest verdict is a reject, which is what the line check gives)
- The set's manifest counts what was left out, by reason, lists those lines, and says whether a
  check ran.

### The set preview

- **MCP tool:** `fichero_training_preview_set` (`GET /api/training/set`), given the teacher, the
  pages, and the held-out pages.
- It shows:
  - pages and lines
  - lines left out, by reason, and which ones
  - whether a check ran
  - the held-out pages
  - anything missing
- It writes nothing and sends nothing.

### The evaluation job

`server/training/evaluation.py`. The job is "Evaluate models on held-out pages".

**What it does.**
- Each candidate reads the lines of the pages' checked pass. By default the readers this Mac
  already has are added for comparison.
- Every page is scored with Fichero's one CER function, under four policies: diplomatic,
  layout-insensitive, lenient, accent-blind.
- Models are ranked by layout-insensitive CER.
- Only models on this Mac can be evaluated; remote ones are refused.

**Held-out pages.**
- With no pages named, the job uses the pages every trained candidate lists as held out on its
  card.
- It refuses, saying why, when a trained model has no held-out pages, or when no page is fair to
  all the candidates.

**Results.**
- Each run is added to the model card's `evaluations`, never replacing an earlier one.
- A run records: when it was measured, the pages, the scores per policy, the scores per page,
  and what it was compared with.

**MCP tools.**
- `fichero_evaluation_start`
- `fichero_evaluation_status`
- `fichero_evaluation_model_scores`

### Defaults taken, awaiting a ruling

- The thresholds: two neighbours, a 0.15 margin, a 0.40 floor, 0.30 low. They come from the
  Sergio project's own check, which found Mosquera's shifted lines (2026-10-04). No ruling in
  the code calls them final.
- The check scores ignoring accents. Evaluation ranks by layout-insensitive CER.
- Evaluation adds the out-of-the-box readers by default.
- Not built:
  - a flagged line shown as flagged in the app
  - the model's **Test** action and its training card (#5439)
  - a check review surface
- The spec names the check tools `fichero_check_run` / `_status` / `_verdicts`
  (`models-chains-and-projects.md:67`). The generated names are the ones listed above.
