# 0.0.2 Feature Gate Map

**Issue:** #381
**Date:** 2026-04-02
**Branch:** `codex/0.0.2-planning`

## Overview

This document maps each 0.0.2 semantic feature to its gate status, promotion criteria, and test evidence requirements. The existing `FICHERO_FEATURE_TIER` (dev/release) controls route registration; the `FeatureFlags` class (designed in `feature-flag-design.md`, not yet implemented) controls per-feature visibility within tiers.

---

## Gate Architecture

| Mechanism | What it controls | Where defined |
|---|---|---|
| `FICHERO_FEATURE_TIER=dev\|release` | Route registration in `main.py` | `fichero-api/src/fichero/api/main.py` |
| `FeatureFlags` class (forthcoming) | Per-feature UI visibility + API behavior | `fichero-api/src/fichero/feature_flags.py` |

**Current state:** All Layer 1-6 routes are in `_DEV_ROUTE_SPECS` — only registered when `FICHERO_FEATURE_TIER=dev`. No per-feature flags exist yet.

## Promotion Checklist

When promoting a feature from **dev → release**, all of the following must be true:

1. **Tests pass:** `ruff check` + `pytest` on all relevant test files
2. **SwiftLint passes:** `swiftlint lint` with zero warnings on affected files
3. **API contracts valid:** OpenAPI schema synced (`./scripts/sync_openapi_schema.sh`)
4. **Swift client builds:** `swift package build` in `fichero-api-client/`
5. **Human QA signed off:** Manual test evidence in issue comments
6. **Feature flag updated:** `FEATURE_X` added to `FeatureFlags` class (when implemented)
7. **Documentation updated:** This gate map and relevant docs reflect new status

## Relationship to Existing Feature Flags

The 0.0.2 knowledge graph features are orthogonal to the existing `FEATURE_DOCUMENTS` / `FEATURE_SEARCH` / etc. flags. Those flags control whether routes are registered at all. The 0.0.2 sub-features are controlled by their presence in `_DEV_ROUTE_SPECS` vs `_CORE_ROUTE_SPECS` (i.e., the `FICHERO_FEATURE_TIER` env var).

Once `FeatureFlags` class is implemented, individual `FEATURE_KG_*` flags can provide finer-grained control (e.g., PyKEEN behind `FEATURE_KG_PREDICTIONS_PYKEEN=1` even in release tier). This is out of scope for #381 but noted here for future work.
