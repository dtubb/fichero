## What Was Fixed

### Issue #4: Large Images Causing Qwen Timeouts (NEW)

**Problem:**
- Large images sent to Qwen API were timing out after 240 seconds
- System would crash or hang on particularly large/complex images
- No fallback strategy - if an image failed at one size, the entire processing failed

**Solution Implemented:**
Progressive image size reduction with automatic retry:
- Try at 1024px (default)
- If timeout → retry at 768px
- If timeout → retry at 512px
- If timeout → retry at 256px
- Only fail if all sizes fail

**Files Modified:**
- `src/fichero/tools/transcribe_qwen_max.py:30-66` - Updated `encode_image()` function
- `src/fichero/tools/transcribe_qwen_max.py:110-233` - Implemented progressive retry logic

**Benefits:**
- Images that would timeout at full size can now succeed at reduced resolution
- Better logging shows which size succeeded (for debugging)
- Reduced timeout from 240s to 180s per attempt (since we have multiple attempts)
- Graceful degradation instead of complete failure

## How the Progressive Sizing Works

When processing an image:

1. **First attempt:** Encode at 1024px, send to Qwen
   - If succeeds → done! ✅
   - If timeout → continue to step 2

2. **Second attempt:** Encode at 768px, send to Qwen
   - If succeeds → done! ✅
   - If timeout → continue to step 3

3. **Third attempt:** Encode at 512px, send to Qwen
   - If succeeds → done! ✅
   - If timeout → continue to step 4

4. **Fourth attempt:** Encode at 256px, send to Qwen
   - If succeeds → done! ✅
   - If timeout → mark as failed ❌

Each size attempt has 2 retries, with exponential backoff (1s, 2s).

**Logs will show:**
```

[15:47:23.234] Encoded image size: 234.5 KB (max_size=1024)

⏱️ Timeout at size 1024px, will try smaller size 768px
[15:48:25.456] Resized image from 3888x5184 to 768x512 (max_size=768)
[15:48:25.567] Encoded image size: 145.2 KB (max_size=768)
```
