## Issue #1: prepare_images Path Resolution Bug

**Status:** ✅ FIXED

**Problem:**
The `prepare_images` tool was incorrectly adding `/documents/` subdirectory to file paths, causing `FileNotFoundError` when processing files that were directly in the `_staging/` folder.

**Symptoms:**
```
[prepare_images] ERROR: Error processing .../staging/documents/EAP1740_NP_T19_1700_001_01.tif:
File not found: .../staging/documents/EAP1740_NP_T19_1700_001_01.tif
```

The file actually existed at: `.../staging/EAP1740_NP_T19_1700_001_01.tif`

**Root Cause:**
In `prepare_images.py:219`, the default value for `add_documents_prefix` parameter was `True`:
```python
add_documents_prefix=kwargs.get('add_documents_prefix', True)  # ❌ Wrong default
```

This caused the `BatchProcessor` to add `/documents/` to paths (see `batch.py:144-145`):
```python
if self.add_documents_prefix and "documents" not in str(self.base_folder) and not str(path).startswith("projects/"):
    full_path = self.base_folder / "documents" / path  # ❌ Adds /documents/
```

**Why This Happened:**
- The plan file (`Default.yml:49`) explicitly specifies `add_documents_prefix: false`
- However, the Python code's fallback default was `True`
- When the parameter wasn't properly passed through the kwargs chain, it used the wrong default
- This caused a mismatch between where `build_documents_manifest` found files and where `prepare_images` looked for them

**Solution:**
Changed the default from `True` to `False` in `prepare_images.py:219`:
```python
add_documents_prefix=kwargs.get('add_documents_prefix', False)  # ✅ Correct default
```

**Files Modified:**
- `src/fichero/tools/prepare_images.py:219` - Changed default value

**Commit:**
- Hash: `0b662ec`
- Message: "Fix prepare_images path resolution bug"


**Impact:**
- ✅ All workflows using `prepare_images` will now find files correctly
- ✅ Respects the `add_documents_prefix: false` setting in plan files
- ✅ Default behavior now matches the most common use case (files directly in `_staging/`)

**Related Code:**
- Path construction logic: `batch.py:142-147`
- Plan configuration: `Default.yml:39-52`
- Manifest generation: `build_documents_manifest.py`

**Notes:**
- The `add_documents_prefix` parameter is still available for workflows that DO need the `/documents/` subdirectory
- Plans can explicitly set `add_documents_prefix: true` if needed
- The fix only changes the default fallback value, not the explicit behavior

## Issue #2: Hardcoded Workflow Name in GUI

**Status:** ✅ FIXED

**Problem:**
The Process button in the GUI was always using the hardcoded "Catalogue" workflow regardless of the selected plan or user preferences. This meant:
- Plans with image enhancement steps (crop, split, rotate, enhance, remove_background) would skip those steps
- Only `prepare_images` → `transcribe` → `catalogue` would run
- User couldn't access full image processing pipeline from GUI

**Symptoms:**
```
User: "I click on an image and it processes but not the default workflow.
       It's just doing transcribe and catalogue, not enhance."
```

**Root Cause:**
In `collection_view.py:2156`:
```python
workflow_name = "Catalogue"  # TODO: Get from plan or settings
```

The workflow was hardcoded instead of reading from:
1. User's saved default workflow preference
2. The plan's default workflow
3. The plan's first workflow

**Solution:**
Changed `collection_view.py:2156-2160` to use `PlanManager.get_default_workflow()`:
```python
# Get default workflow for the plan
workflow_name = PlanManager.get_default_workflow(plan_name, self.app)
if not workflow_name:
    workflow_name = "Catalogue"  # Fallback if no workflow found
    logger.warning(f"No default workflow found for plan {plan_name}, using fallback: {workflow_name}")
logger.info(f"Plan: {plan_name}, Workflow: {workflow_name}")
```

**How It Works Now:**
1. **Get default plan** from settings (e.g., "Default" or "Enhance_Images_and_Catalogue")
2. **Get default workflow** for that plan:
   - First tries user's saved default workflow preference
   - Falls back to "default" workflow if it exists in plan
   - Falls back to first workflow in plan
   - Falls back to "Catalogue" only if nothing else works
3. **Process with correct workflow**

**Files Modified:**
- `src/fichero/windows/main/views/collection/collection_view.py:2156-2160`

**Commit:**
- Hash: `da45480`
- Message: "Fix hardcoded workflow name in GUI processing"

**Testing:**

**Option 1:** Change default plan to one with image steps


Then restart GUI and click Process - it will use "Default" workflow from that plan which includes all image enhancement steps.

**Option 2:** Keep "Default" plan but change its workflow
The "Default" plan has only the "Catalogue" workflow which skips image enhancement. To get full processing, either:
- Use "Enhance_Images_and_Catalogue" plan (Option 1)
- Or modify Default.yml to add a workflow with image steps

**Impact:**
- ✅ GUI now respects plan/workflow preferences
- ✅ Can access full image processing pipeline from GUI
- ✅ Workflow selection is consistent between GUI and CLI

## Issue #3: Plan Name Mismatch (Title vs Filename)

**Status:** ✅ FIXED

**Problem:**
The Settings window was saving plan **titles** (display names) but the code was expecting plan **filenames**. This caused the system to fail finding the selected plan and fall back to the wrong plan/workflow.

**Symptoms:**
```
User: "but I try to run it just on 1 image and it doens't work"

Logs showed:
WARNING - Settings default plan 'Enhance, Transcribe, and Catalogue' no longer exists
WARNING - Saved default plan 'Enhance, Transcribe, and Catalogue' no longer exists
DEBUG - Using first available plan: Default_English
DEBUG - Using first available workflow: Catalogue
Plan: Default_English, Workflow: Catalogue
```

User selected "Enhance, Transcribe, and Catalogue" in Settings, but it used "Default_English" → "Catalogue" instead.

**Root Cause:**
The Settings window dropdown shows plan **titles** from the YAML files:
- Settings saves: "Enhance, Transcribe, and Catalogue" (title from YAML)
- But the actual filename is: "Enhance_Images_and_Catalogue.yml"

When `PlanManager.get_default_plan()` returned the title, the rest of the code couldn't find a file with that name, so it fell back to the first available plan.

**Why This Happened:**
1. `get_available_plans()` returns **display names (titles)** for the UI (line 76-79 in `plan_manager.py`)
2. Settings saves the selected title: "Enhance, Transcribe, and Catalogue"
3. `get_default_plan()` checks if the saved value exists in available plans (line 328)
4. The check passes because the title exists in the list
5. `get_default_plan()` returns the title as-is (line 330)
6. Later code tries to find file "Enhance, Transcribe, and Catalogue.yml" which doesn't exist
7. System falls back to first available plan

**Solution:**
Modified `PlanManager.get_default_plan()` to convert display names to filenames before returning:

```python
# In plan_manager.py:329-335
if settings_default in valid_plans:
    logger.debug(f"Using default plan from settings: {settings_default}")
    # Convert display name to filename if needed
    filename_stem = PlanManager.get_plan_filename_from_display_name(settings_default, app)
    if filename_stem:
        logger.debug(f"Converted plan display name '{settings_default}' to filename '{filename_stem}'")
        return filename_stem
    return settings_default
```

Applied the same conversion to all 3 return paths:
1. Settings default (line 329-335)
2. Shared data fallback (line 350-357)
3. First available plan fallback (line 367-375)

**Files Modified:**
- `src/fichero/config/core/plan_manager.py:329-335` - Convert title to filename for settings default
- `src/fichero/config/core/plan_manager.py:350-357` - Convert title to filename for shared data fallback
- `src/fichero/config/core/plan_manager.py:367-375` - Convert title to filename for first available fallback
- `src/fichero/config/core/plan_manager.py:309-318` - Updated docstring to clarify return value

**How It Works Now:**
1. Settings saves: "Enhance, Transcribe, and Catalogue" (title)
2. `get_default_plan()` reads: "Enhance, Transcribe, and Catalogue"
3. `get_default_plan()` converts to: "Enhance_Images_and_Catalogue" (filename)
4. Returns the filename to calling code
5. Code successfully finds and loads: "Enhance_Images_and_Catalogue.yml"
6. Uses the correct "Default" workflow from that plan with all image enhancement steps

**Existing Infrastructure Used:**
- `PlanManager.get_plan_filename_from_display_name()` already existed at line 215-258
- This method searches all plan files for matching titles and returns the filename
- It also handles direct filename matches as a fallback
