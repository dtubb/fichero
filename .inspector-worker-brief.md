## The plan in one paragraph
The DocumentInspector goes from 10 tabs to **4: Source, Artifacts, Knowledge,
Notes**. It is the per-selection **database editor + navigator** (scope =
current document OR its children); the Reader owns visualization. There are
TWO parallel Swift trees today — `Views/Library/DocumentInspector/` (tabbed,
with cruft: `ContentV2`, KG/Entities bolted under `ArtifactsTab+…`,
Citations/Bibliography under `InfoTab+…`, `MetadataTab` vs `InfoTab`) and
`Views/Library/Inspector/` (clean reusable `*Pane` components). Consolidate
onto the reusable panes; delete cruft. Engine routes already exist under
`fichero-engine/src/fichero/api/routes/` — the gap is UI exposure, not backend.

## Hard rules
- **Iterate, never rewrite.** Reuse existing components. KEEP the entity
  **Lozenge**, `MiniToolbar.swift`, `OntologyBrowser`, and the `Inspector/*Pane`
  set. Build shared chrome as reusable components (WorkflowInspector reuses them later).
- **Best-practice native SwiftUI.** `List` for flat selection, `Table`/OutlineView
  for hierarchical/columnar. Semantic system fonts. No custom/hacky UX.
- **OpenAPI-only transport** (generated client) + `@Observable` stores own
  fetch/mutation. No hand-rolled URLSession, no view-local state, no
  NotificationCenter for app state, no singleton service lookups.
- **No wholesale list re-render** — update one item in place, stable identity.
- **Commit-only.** Do NOT run `xcodebuild`/full test suite (the manager gates
  builds serially via Xcode MCP — Daniel's machine can't run parallel builds).
  You MAY run `swiftlint` and compile-check individual files. Write tests; the
  manager runs them.
- New `.swift` files need `project.pbxproj` membership — flag any you add so
  the manager fixes membership.
